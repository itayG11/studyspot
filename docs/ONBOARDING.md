# הצטרפות של מוסד חדש ל-StudySpot

מדריך קצר למוסד שרוצה להשתמש באתר. אין התקנה ואין קוד: המוסד מקבל כתובת משלו באתר, ומקים בה את הקמפוס.

## מה המוסד מקבל

| מה | פירוט |
|---|---|
| כתובת משלו | למשל `https://studyspot-yetb.onrender.com/tel-hai` |
| חיפוש מקום | הסטודנטים מוצאים מקום פנוי, ומזמינים חדרים ותאים |
| שלטים | שלט עם קוד `QR` לכל מקום. הסטודנטים סורקים אותו כשהם מגיעים |
| דף ניהול | בניינים, מקומות, מיקום על המפה ושלטים |

## הרבה בניינים בבת אחת: העלאת טבלה

- **איפה:** בדף הניהול, לשונית "הוספה", בכרטיס "הרבה בניינים בבת אחת".
- **התבנית:** מורידים את "תבנית אקסל" או "תבנית CSV" מאותו כרטיס, וממלאים שורה לכל מקום.

| עמודה | חובה | הערה |
|---|---|---|
| שם קצר | כן | אותיות באנגלית, ספרות ומקף, כמו `M` |
| שם הבניין | לא | השם המלא |
| מספר קומות | כן | מספיק בשורה הראשונה של הבניין |
| סוג המקום | לשורת מקום | חדר לימוד קבוצתי, מתחם לימוד פתוח, ספרייה או חוות מחשבים |
| שם המקום | לשורת מקום | כמו `M206` |
| קומה | לשורת מקום | הכניסה היא קומה 0 |
| כמה אנשים | לכל סוג חוץ מחוות מחשבים | |
| שורות, עמדות בשורה | לחוות מחשבים | נוצרת עמדה לכל שורה ועמודה |
| קו רוחב, קו אורך | לא | בלי מיקום, ממקמים אחר כך ב"מיקום בניינים" |
| הערת מיקום | לא | למשל "משמאל למעלית" |

- **שורה בלי פרטי מקום** מוסיפה בניין בלבד.
- **לפני השמירה** מוצג מה נמצא בטבלה, ושורות עם בעיה מסומנות עם מספר השורה והסיבה. שום דבר לא נשמר עד שמאשרים.
- **בניין שכבר קיים:** בוחרים אחת משלוש:

| אפשרות | מה קורה |
|---|---|
| להוסיף את המקומות החדשים | המקומות החדשים נוספים. מקום שכבר קיים באותו שם מדולג |
| להשאיר כמו שהוא | השורות שלו בטבלה מדולגות |
| למחוק ולהוסיף מחדש מהטבלה | הבניין נמחק עם המקומות, השלטים וההזמנות שבו, ונוצר מחדש מהטבלה. לפני כן מוצג כמה ימחקו. שיעורים של סטודנטים בבניין נשמרים, וחוזרים לבניין החדש |

- **הכול או כלום:** אם שורה אחת נדחית בשמירה, לא נשמר כלום, ומופיעה הסיבה.
- **שעות פתיחה:** כל מקום חדש מקבל את שעות ברירת המחדל, כמו בטופס.

## מה צריך ממנהל המחשוב של המוסד

- **כניסה במייל של המוסד:** סיומת המייל של הסטודנטים, למשל `e.braude.ac.il`. נשלח לסטודנט קוד חד-פעמי למייל.
- **כניסה עם מיקרוסופט של המוסד:** מנהל המחשוב מאשר את האפליקציה פעם אחת, בקישור, בשם כל הארגון. בלי האישור הזה, הסטודנטים רואים "דרוש אישור מנהל מערכת".
- **הגדרת כללי הכניסה:** בדף הניהול, בלשונית "הקמה", צעד 2. שם מוסיפים את סיומת המייל ואת מזהה הארגון של מיקרוסופט, ושם מופיע קישור האישור למנהל המחשוב.
- **אישור הכללים:** כלל חדש עובד רק אחרי שמנהל המערכת בדק שהסיומת או הארגון באמת של המוסד. עד אז מופיע לידו "ממתין לאישור מנהל המערכת". בעתיד, אימות אוטומטי ברשומת `DNS` יחליף את הבדיקה הידנית.
