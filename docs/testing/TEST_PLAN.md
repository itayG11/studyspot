# תוכנית הבדיקות של StudySpot

**מה יש כאן:**
- **מה בודקים:** כל עמוד, לכל תפקיד, וכל מצב חשוב בו.
- **איך כל דבר נבדק, ובאיזה קובץ.**
- **מה עדיין לא נבדק, ולמה.**

**סבב הבדיקות:** נכתב בסבב הבדיקות של 25.10.2026, לפני גל 15. הממצאים, עם החומרה, ההוכחה והתיקון, נמצאים ב-[`FINDINGS.md`](FINDINGS.md).

## איך מסמנים "איך נבדק"
| סימון | פירוש |
|---|---|
| **אוטומטי** | טסט שרץ בכל דחיפה ב-`CI`, עם שם הקובץ |
| **חדש** | טסט אוטומטי שנוסף בסבב הזה |
| **ידני** | בדיקה שלי בדפדפן, עם צילום מסך בתיקיית ההוכחות |
| **אצלך** | רק אתה יכול לבדוק, למשל בטלפון אמיתי או במייל אמיתי |
| **לא נבדק** | עם הסיבה |

**שים לב:** טסט שקיים בקוד הוא לא הוכחה בפני עצמו. בסוף הסבב הרצתי את כולם, והתוצאות ב-`FINDINGS.md`.

## חמש שכבות הבדיקה

| שכבה | הכלי | מה היא בודקת | איפה |
|---|---|---|---|
| טסטי שרת | `pytest`, מול `PostgreSQL` אמיתי | כללים, הרשאות, אילוצי מסד הנתונים, ומקביליות | `backend/tests/`, 70 קבצים |
| טסטי יחידה של האתר | `vitest`, עם `Testing Library` | רכיב אחד או לוגיקה אחת, בלי שרת | `frontend/src/**/*.test.ts*`, 89 קבצים |
| טסטים בדפדפן | `Playwright`, מול השרת והמסד | מסלול מלא, כמו משתמש | `frontend/e2e/*.spec.ts` |
| שלושה מכשירים | `Playwright` על גרסת הייצור | מחשב, `iPad` וטלפון, עם הכותרות של האתר החי | `playwright.edge.config.ts`: `edge.spec.ts`, `sweep.spec.ts` |
| נגישות | `axe`, דרך `@axe-core/playwright` | בעיות נגישות אוטומטיות, כמו ניגודיות, שמות לכפתורים ושפת הדף | `a11y.spec.ts`, `sweep.spec.ts` |

**הרצה:**
- `cd backend && pytest -q`
- `cd frontend && npx vitest run`
- `npx playwright test`
- `npx playwright test -c playwright.edge.config.ts`
